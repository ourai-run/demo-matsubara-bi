# マツバラ 月次業績・経営分析

株式会社マツバラ（小物鋳鉄鋳物）の予実管理・月次業績報告のためのシステムです。
各部署から届く Excel / CSV を入れると、予算との差を要因に分けて集計し、AI が示唆を出します。
役員会での判断と理由を記録すると、AI がその「考え方」を覚え、翌月の示唆に反映します。

表示されている数字はすべてサンプルデータです（得意先名は同社の公開情報、数字は架空）。

## 毎月の流れ

1. **データ取込** — 5種類のファイル（売上・生産・材料・経費・人件費）を枠に入れる。種類・年月・単位は自動で見分ける。
2. **AI分析** — その月の実績が5種類そろうと自動で実行。数字の計算はシステム側で行い、AI は読み解きだけを行う。
3. **月次ダッシュボード** — 示唆は、該当する図や表の場所に番号で表示される（番号を押すと右側に詳細）。
4. **役員会** — 示唆ごとに「対応する／静観する／問題なし／別の判断」と理由を記録。議事メモを貼って読み取らせることもできる。
   理由から AI が考え方の案を作り、承認したものが翌月以降の示唆に使われる。
5. **月次報告書** — 現行の月次資料に近い形で出力（印刷・PDF、Excel）。確定すると所見が固定される。

## 画面

| 画面 | 内容 |
| --- | --- |
| 月次ダッシュボード | 総括、主要指標、営業利益の差異分解（予算→実績）、売上（分野・得意先）、重量当たりの採算、生産ライン、材料、経費・人件費、推移 |
| 切り口分析 | 見る数字 × 分け方 × 期間 × 比較を選ぶだけの集計。表の行を押すと絞り込んで掘り下げる |
| 役員会 | 示唆ごとの議論・判断、議事メモの読み取り、決定事項のフォロー、AI が覚えた考え方の管理 |
| 月次報告書 | 月次業績報告書（印刷・PDF保存、Excel 出力、確定） |
| 着地見込み・試算 | 年度末の着地見込みと、数量・単価・材料価格などを動かした試算 |
| データ取込 | ファイルの取込、取込状況、取込履歴、取込用サンプルファイル |
| データ一覧 | 取り込んだ明細の検索・CSV 保存（過去の月も参照） |
| 右側の AI | 今月の示唆の一覧・詳細と、数字についての質問（必要なデータは AI が自分で集計して答える） |

## 取り込むファイル

Excel（.xlsx / .xls）と CSV（UTF-8 / Shift_JIS）。1行目が表題でも、見出しの行を探して読みます。

| 種類 | 出どころ | 必要な列（別名も可） | あれば読む列 |
| --- | --- | --- | --- |
| 売上実績 | 営業・生産管理 | 得意先、分野、品目群、重量、売上金額 | 区分、数量 |
| 生産実績 | 関工場 製造 | ライン、稼働時間、注湯重量、良品重量、不良重量 | 稼働日数 |
| 材料使用実績 | 購買・資材 | 材料名、使用量、材料費 | 材料区分 |
| 経費実績 | 経理 | 部門、科目、金額 | 固変区分 |
| 人件費・勤怠 | 総務 | 部門、人員、残業時間、人件費 | — |

- **年月**：「年月」の列、またはファイル名・シート名・表題（`2026年11月` `2026/11` `202611` `R8.11`）から読みます。
- **予算**：「予実」の列に「予算」と入れるか、ファイル名に「予算」を入れます。予算と実績が混ざった表は分けて取り込みます。
- **単位**：見出しに `(千円)` `(t)` などがあれば円・kg に換算します。
- **合計の行**は取り込みません。同じ種類・同じ月を入れ直すと置き換えます（置き換えの前に確認します）。
- 全角・半角だけが違う名称は、取込済みの表記にそろえます。それ以外の新しい名称は注意として表示します。
- 見出しが上の形に合わない表は、AI が列を見分けます（内容を確認してから取込）。
- 列の定義は `lib/model.ts` の `KINDS` にあります。別名を足すときもここです。

## AI

OpenAI API を使います。数字は `lib/analytics.ts` が計算し、AI にはその結果だけを渡します（AI に計算はさせません）。

| 機能 | 内容 |
| --- | --- |
| 月次の示唆 | 総括、示唆 4〜7 件（状況・要因・提案・論点・根拠の数字・図表上の場所）、考え方に沿って指摘を控えた項目 |
| 考え方の学習 | 役員会の判断と理由から、来月以降も使える判断基準を取り出す（人が承認・修正・却下） |
| 議事メモの読み取り | 書き起こしやメモから、示唆ごとの判断・理由・決定事項を読み取る |
| 質問への回答 | 蓄積データを集計する道具を使って回答し、切り口分析の画面も用意する |
| 列の見分け | 見出しが決まった形でないファイルの列を判定する |

| 環境変数 | 内容 |
| --- | --- |
| `OPENAI_API_KEY` | 必須。未設定のときは AI の機能だけがエラー表示になり、集計や報告書は使えます |
| `OPENAI_MODEL` | 省略時 `gpt-6.2-sol`。Structured Outputs と Responses API（function tools）に対応したモデル |
| `OPENAI_BASE_URL` | 省略時 `https://api.openai.com/v1` |

## 開発

Node.js 22.13 以上。

```bash
npm install
cp .dev.vars.example .dev.vars   # OPENAI_API_KEY を入れる
npm run dev                      # http://127.0.0.1:5173
```

```bash
npm test         # 差異分解の一致、取込の読み取りなど
npm run lint
npm run build    # dist/ に出力
npm start        # ビルドしたものをローカルで実行
```

初回のアクセス時に、表の作成とサンプルデータ（2024年4月〜2026年10月の実績、2027年3月までの予算、7〜10月の示唆・役員会の判断・覚えた考え方）の投入を自動で行います。
2026年11月分は「データ取込」画面のサンプルファイルから取り込めます。「サンプルデータに戻す」で初期状態に戻ります。

## chatgpt.site での公開

chatgpt.site（Sites）向けの構成です（vinext ＋ Cloudflare Workers ＋ D1）。

- `.openai/hosting.json` で D1 を `DB` として使います。`project_id` は入れていないので、公開時に新しいプロジェクトとして作られます。
- 表の定義は `drizzle/` にあり、ビルド時に `dist/.openai/drizzle/` へコピーされます。
- 公開先のシークレットに `OPENAI_API_KEY` を設定してください。
- ログイン機能はありません。閲覧できる人の制限は chatgpt.site 側のアクセス設定で行います。画面右上の「操作者」は記録に残す名前の切り替えです。

## 構成

```
app/            画面の入口と API（/api/state 全データ、/api/rpc 更新、/api/chat 質問）
components/     画面（dashboard / explore / board / report / forecast / data / ai-panel）
lib/analytics.ts  損益・差異分解・切り口集計・着地見込み・AI に渡す数値
lib/parse.ts      ファイルの読み取り（種類・年月・単位の判定）
lib/sample*.ts    サンプルデータと取込用サンプルファイル
lib/server/       D1 の読み書き、AI の呼び出しと指示文、更新処理
drizzle/, db/     表の定義（records 1表に JSON で保存）
docs/要件資料/    ヒアリング時の要件資料
```

想定は利用者5名ほど・月次データです。全データを最初に1回で読み込む作りなので、明細が数万行を超える使い方をするときは `/api/state` を月ごとの取得に分けてください。
